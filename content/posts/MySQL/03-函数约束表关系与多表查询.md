> [MySQL 入门指南](./00-MySQL入门指南.md) · 第三章：表达数据关系，并检查关联后的结果粒度。

本章沿用第一、二章的表与固定数据。函数负责计算表达式，约束负责阻止不合法写入，连接与子查询负责组合数据。多表查询时，需要随时确认：**关联之后，一行到底代表什么。**

## 一、常用函数：计算与展示

### 字符串

| 函数 | 作用 | 示例 |
| --- | --- | --- |
| `CONCAT` | 拼接，任一参数为 NULL 时结果为 NULL | `CONCAT('My', 'SQL')` |
| `CONCAT_WS` | 使用分隔符拼接，跳过后续 NULL 参数 | `CONCAT_WS('-', 'A', NULL, 'B')` |
| `LOWER`、`UPPER` | 转换大小写 | `LOWER('MySQL')` |
| `LPAD`、`RPAD` | 填充至指定字符长度，过长时也可能截短 | `LPAD('7', 4, '0')` |
| `TRIM` | 默认移除两端普通空格 | `TRIM('  abc  ')` |
| `SUBSTRING` | 按字符位置截取，常用起点从 1 开始 | `SUBSTRING('MySQL', 1, 2)` |
| `REPLACE` | 替换子串 | `REPLACE('abc', 'b', 'B')` |
| `LENGTH` | 字节数 | `LENGTH('中国')` |
| `CHAR_LENGTH` | 字符数 | `CHAR_LENGTH('中国')` |

```sql
SELECT name,
       COALESCE(nickname, name) AS display_name,
       CHAR_LENGTH(name) AS name_characters
FROM emp
ORDER BY id;
```

`COALESCE` 返回第一个非 NULL 参数；空字符串并不是 NULL。如果空昵称也要退回姓名，可以使用 `COALESCE(NULLIF(nickname, ''), name)`。

### 数值

| 函数 | 用途 |
| --- | --- |
| `CEIL`、`FLOOR` | 向上、向下取整 |
| `ABS` | 绝对值 |
| `MOD` | 取余 |
| `ROUND` | 按指定小数位舍入，行为还与精确值或近似值类型有关 |
| `POWER`、`SQRT` | 幂与平方根 |
| `RAND` | 生成伪随机数，不适合生成安全令牌或密码 |

```sql
SELECT CEIL(1.1), FLOOR(1.9), MOD(7, 4), ROUND(2.345, 2);
```

金额计算应保留明确的精度和舍入规则，不能只在页面上格式化两位小数就认为底层计算已经准确。

### 日期与时间

```sql
SELECT NOW(), CURDATE(), CURTIME();
SELECT DATE_ADD('2026-01-01', INTERVAL 7 DAY);
SELECT DATE_FORMAT('2026-10-26 09:30:00', '%Y-%m-%d %H:%i:%s');

SELECT id, name, DATEDIFF(CURDATE(), entry_date) AS employed_days
FROM emp
ORDER BY employed_days DESC, id;
```

`DATEDIFF` 计算日期部分的天数差，不是按秒计算完整时长。`DATE_FORMAT` 中 `%i` 表示分钟，`%m` 表示月份。

查询某一天的 DATETIME 数据时，半开区间通常比对整列套 `DATE()` 更适合利用普通索引：

```sql
SELECT id, name, created_at
FROM emp
WHERE created_at >= '2026-10-26 00:00:00'
  AND created_at <  '2026-10-27 00:00:00';
```

是否返回数据取决于实际写入时间，日期边界也必须与字段的时区约定一致。

### 条件表达式

```sql
SELECT id, name,
       IF(status = 1, '在职', '非在职') AS employment_status,
       CASE
           WHEN salary >= 12000 THEN '较高'
           WHEN salary >= 9000 THEN '中等'
           ELSE '其他'
       END AS salary_band
FROM emp
ORDER BY id;
```

`CASE` 按顺序选择第一个满足的分支。`IFNULL(a,b)` 在 a 为 NULL 时返回 b；`COALESCE` 可以依次检查多个候选值。

## 二、约束表达什么规则

| 机制 | 规则 | 本套示例 |
| --- | --- | --- |
| `PRIMARY KEY` | 唯一标识行，非空 | `emp.id` |
| `NOT NULL` | 必须提供非 NULL 值 | `emp.name` |
| `UNIQUE` | 防止重复键值 | `emp.work_no` |
| `CHECK` | 拒绝表达式为假的写入 | `salary >= 0` |
| `FOREIGN KEY` | 引用必须符合父子关系 | `emp.dept_id → dept.id` |
| `DEFAULT` | 未指定时提供默认值 | `status DEFAULT 1` |

默认值是取值规则，不能替代有效性约束。MySQL 8.0.16 之前对 CHECK 的支持与之后不同，本指南所用 8.4 会执行已启用的检查。

`CHECK` 的表达式为真或未知时通常允许通过，因此要禁止 NULL 还需要 `NOT NULL`。唯一索引通常允许多个 NULL，不能把 `UNIQUE` 当作“必填”。

一张表只能有一个主键，但主键可以由多列组成。自增列不等于业务上的连续编号，主键也不要求必须使用自增整数。

## 三、外键与表关系

### 一对多：部门与员工

一个部门可以对应多个员工。外键放在“多”的一侧，也就是 `emp.dept_id`。

InnoDB 外键需要合适的索引，关联列的类型和符号等属性应兼容；字符串关联还涉及字符集和排序规则。跨表引用优先使用主键或唯一候选键，不依赖非标准的非唯一引用行为。

| 父表删除或更新策略 | 结果 |
| --- | --- |
| `RESTRICT`、`NO ACTION` | 对 InnoDB，通常在语句执行时拒绝破坏已有引用的操作 |
| `CASCADE` | 相应级联更新或删除子表记录 |
| `SET NULL` | 子表外键设为 NULL，要求列允许 NULL |

本套示例使用 `ON DELETE SET NULL`：删除部门时员工仍保留，部门编号变为 NULL。这是一种业务选择，不能把级联删除设为所有关系的默认策略。

外键不会自动证明“上级一定与员工同部门”，自引用外键也不能单独排除所有管理层级环路。这些跨记录业务规则仍需要额外设计。

### 多对多：员工与技能

下面增加本章使用的技能及关联表。建表与写入分别执行一次：

```sql
CREATE TABLE skill (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_skill_name (name)
) ENGINE = InnoDB;

CREATE TABLE emp_skill (
    emp_id BIGINT UNSIGNED NOT NULL,
    skill_id BIGINT UNSIGNED NOT NULL,
    PRIMARY KEY (emp_id, skill_id),
    CONSTRAINT fk_emp_skill_emp FOREIGN KEY (emp_id)
        REFERENCES emp(id) ON DELETE CASCADE,
    CONSTRAINT fk_emp_skill_skill FOREIGN KEY (skill_id)
        REFERENCES skill(id) ON DELETE CASCADE
) ENGINE = InnoDB;

INSERT INTO skill (id, name)
VALUES (1, 'SQL'), (2, 'Linux'), (3, 'Java');

INSERT INTO emp_skill (emp_id, skill_id)
VALUES (1, 1), (1, 2), (2, 1), (3, 2), (4, 3);
```

联合主键防止同一员工重复关联同一技能。技能名称作为独立数据保存，避免在员工列里放逗号分隔的多个技能。

### 一对一：员工与详情

```sql
CREATE TABLE emp_profile (
    emp_id BIGINT UNSIGNED NOT NULL,
    bio VARCHAR(200) NULL,
    PRIMARY KEY (emp_id),
    CONSTRAINT fk_emp_profile_emp FOREIGN KEY (emp_id)
        REFERENCES emp(id) ON DELETE CASCADE
) ENGINE = InnoDB;
```

主键同时作为外键，使每位员工至多有一份详情；员工可以暂时没有详情。因此这里准确表达的是一对零或一，并不强制每个员工都必须存在详情行。

## 四、内连接、外连接与自连接

### 内连接：只返回匹配行

```sql
SELECT e.id, e.name AS employee_name, d.name AS department_name
FROM emp AS e
INNER JOIN dept AS d ON d.id = e.dept_id
ORDER BY e.id;
```

固定数据返回 5 位已分配部门的员工，周然不在结果中。没有连接条件可能产生笛卡尔积，即每行与另一表的每行组合。

### 左连接：保留左表行

```sql
SELECT e.id, e.name, d.name AS department_name
FROM emp AS e
LEFT JOIN dept AS d ON d.id = e.dept_id
ORDER BY e.id;
```

这里保留全部 6 位员工，周然对应的部门名称为 NULL。右连接按相反方向保留，也可以通过交换表顺序改写为左连接。

### ON 与 WHERE：先决定匹配，再过滤结果

查询所有部门及其在职员工：

```sql
SELECT d.id AS dept_id, d.name AS department_name, e.name
FROM dept AS d
LEFT JOIN emp AS e
    ON e.dept_id = d.id
   AND e.status = 1
ORDER BY d.id, e.id;
```

如果把 `e.status = 1` 移到 WHERE，设计部的空值占位行就会被过滤掉。外连接中的条件位置会改变结果含义，不能机械互换。

### 自连接：同一张表的不同角色

```sql
SELECT e.id, e.name AS employee_name, m.name AS manager_name
FROM emp AS e
LEFT JOIN emp AS m ON m.id = e.manager_id
ORDER BY e.id;
```

`e` 与 `m` 分别代表员工和上级，即使来自同一张表，也需要不同别名说明角色。

## 五、聚合前检查连接是否放大了行数

统计所有部门的在职员工人数：

```sql
SELECT d.id, d.name, COUNT(e.id) AS active_employee_count
FROM dept AS d
LEFT JOIN emp AS e
    ON e.dept_id = d.id AND e.status = 1
GROUP BY d.id, d.name
ORDER BY d.id;
```

固定结果为研发部 2 人、市场部 2 人、设计部 0 人。不能使用 `COUNT(*)` 替代，因为没有员工的部门也会保留一行占位结果。

如果再连接 `emp_skill`，一位员工可能产生多行。此时人数可按需求使用 `COUNT(DISTINCT e.id)`，但薪资不能简单改成 `SUM(DISTINCT salary)`，因为不同员工可能恰好同薪。

更稳妥的方式是先按目标粒度汇总，再连接：

```sql
SELECT d.id, d.name,
       COALESCE(s.employee_count, 0) AS employee_count,
       COALESCE(s.total_salary, 0) AS total_salary
FROM dept AS d
LEFT JOIN (
    SELECT dept_id, COUNT(*) AS employee_count,
           SUM(salary) AS total_salary
    FROM emp
    WHERE status = 1
    GROUP BY dept_id
) AS s ON s.dept_id = d.id
ORDER BY d.id;
```

## 六、子查询与 EXISTS

| 类型 | 结果形状 | 主要约束 |
| --- | --- | --- |
| 标量子查询 | 至多一行一列 | 多于一行报错，零行作为 NULL |
| 列子查询 | 多行一列 | 常与 IN、ANY、ALL 等配合 |
| 行子查询 | 一行多列 | 列数与比较对象对应 |
| 派生表 | 多行多列 | FROM 中使用并赋予别名 |

标量子查询：

```sql
SELECT id, name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp)
ORDER BY id;
```

不要因为“姓名看起来唯一”，就拿姓名查询当作保证单行的标量来源。需要唯一定位时使用主键或唯一键。

相关子查询：

```sql
SELECT e.id, e.name, e.salary
FROM emp AS e
WHERE e.salary < (
    SELECT AVG(e2.salary)
    FROM emp AS e2
    WHERE e2.dept_id = e.dept_id
)
ORDER BY e.id;
```

外层部门为 NULL 时，普通等值比较不会把所有“部门未知”员工自动当成一个相同部门。是否需要特殊处理，应由业务含义决定。

检查存在性：

```sql
SELECT d.id, d.name
FROM dept AS d
WHERE EXISTS (
    SELECT 1 FROM emp AS e
    WHERE e.dept_id = d.id AND e.status = 1
);
```

EXISTS 关心是否返回行，不关心选择了哪些列。优化器可能进行改写，不能仅按文本嵌套层数推断实际执行次数或性能。

## 七、UNION 与完整保留两侧数据

```sql
SELECT id, name FROM emp WHERE dept_id = 1
UNION ALL
SELECT id, name FROM emp WHERE salary >= 10000;
```

`UNION ALL` 保留重复行，`UNION` 按整行去重。两侧列数必须一致，对应类型要能按规则合并。需要最终排序时，在合并结果层明确排序。

MySQL 没有直接的 `FULL OUTER JOIN` 语法。下面保留全部员工，同时保留没有员工的部门：

```sql
SELECT e.id AS emp_id, e.name AS employee_name,
       d.id AS dept_id, d.name AS department_name
FROM emp AS e
LEFT JOIN dept AS d ON d.id = e.dept_id
UNION ALL
SELECT e.id, e.name, d.id, d.name
FROM dept AS d
LEFT JOIN emp AS e ON e.dept_id = d.id
WHERE e.id IS NULL;
```

第二部分只补充右侧独有行，避免重复加入已经匹配的数据。

## 八、语句速查

| 需求 | 常用方式 |
| --- | --- |
| 缺失值回退 | `COALESCE`、`IFNULL` |
| 条件分类 | `CASE WHEN ... THEN ... END` |
| 只保留匹配 | `INNER JOIN ... ON ...` |
| 保留一侧全部记录 | `LEFT JOIN ... ON ...` |
| 判断有无关联记录 | `EXISTS`、`NOT EXISTS` |
| 多对多 | 中间表＋联合唯一约束或主键 |
| 避免聚合翻倍 | 先按目标粒度汇总，再进行关联 |
| 合并结果保留重复 | `UNION ALL` |
