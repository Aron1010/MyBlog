安装一个软件之后，还需要知道它由哪个命令启动、是否作为服务运行、配置从哪里读取，以及相关数据如何备份。本篇把这些日常操作串起来，建立一套基本的环境管理思路。

**先确认发行版和管理工具，再执行对应命令。** 本文同时列出 Debian/Ubuntu 与使用 DNF 的 RPM 系统示例，选择适合当前系统的一组即可。带 `sudo` 的命令表示操作通常需要管理员权限。

## 一、软件包管理：先分清工具层次

查看系统信息：

```bash
cat /etc/os-release
```

| 系统或工具 | 常见命令 | 主要职责 |
| --- | --- | --- |
| Debian、Ubuntu 等 | `apt` | 查询软件仓库、处理依赖并管理软件 |
| Fedora、RHEL 系等采用 DNF 的系统 | `dnf` | 管理 RPM 软件及依赖 |
| 旧教程或部分兼容环境 | `yum` | RPM 系统的软件管理入口，具体实现取决于版本 |
| RPM 软件包工具 | `rpm` | 查询、安装或升级 RPM 包，本身不自动从仓库补齐依赖 |

优先通过系统仓库安装软件，软件更新、依赖管理和卸载都会更方便。安装前先阅读包管理器列出的变更，确认将新增或移除哪些软件。

### APT：Debian 与 Ubuntu 常见操作

下面以安装 `curl` 为例：

```bash
sudo apt update
apt search curl
apt show curl
sudo apt install curl
```

`apt update` 更新本地软件包索引，**不会直接升级已安装软件**。升级使用：

```bash
sudo apt upgrade
```

卸载软件：

```bash
sudo apt remove curl
```

`remove` 通常保留软件包管理的配置文件；需要一并清理这类配置时可使用 `purge`。这不等于删除所有用户数据，应根据具体软件确认保留范围。

### DNF：RPM 系统常见操作

```bash
dnf search curl
dnf info curl
sudo dnf install curl
dnf list --installed
sudo dnf upgrade
sudo dnf remove curl
```

| 命令 | 用途 |
| --- | --- |
| `dnf repolist` | 查看启用的软件仓库 |
| `dnf check-update` | 检查可更新软件 |
| `sudo dnf clean all` | 清理缓存 |
| `sudo dnf install ./package.rpm` | 安装本地 RPM，并尝试从已配置仓库解决依赖 |

`dnf check-update` 在发现更新时可能返回状态码 `100`，这并不表示普通的执行失败。

旧环境中的 `yum install`、`yum remove`、`yum update` 分别对应安装、卸载和更新。不要直接套用其他发行版或其他版本的软件源文件。

如果使用本地安装介质作为软件源，需要先挂载匹配的介质，再按发行版的仓库格式配置 `baseurl` 和签名密钥，最后检查仓库是否可用。仓库布局可能包含多个子目录，不能假设挂载根目录就是软件源，也不应把关闭签名校验作为默认步骤。

### RPM：查询包与文件归属

```bash
rpm -q bash
rpm -qa
rpm -qi bash
rpm -ql bash
rpm -qf /usr/bin/bash
```

分别用于查询单个包、列出已安装包、查看详情、查看包内文件，以及查询文件属于哪个包。文件路径应以当前系统实际位置为准。

直接安装或升级本地包：

```bash
sudo rpm -ivh package.rpm
sudo rpm -Uvh package.rpm
```

第二种方式会升级已有软件，未安装时也可安装。遇到依赖问题时，优先使用 DNF 处理，不要靠忽略依赖强行安装。

## 二、下载文件：wget 与 curl

`wget` 适合直接下载文件；`curl` 既能下载，也常用于测试接口。以下地址仅展示格式，使用时替换为实际下载地址：

```bash
wget -O package.tar.gz 'https://example.com/download/package.tar.gz'
curl -fL -o package.tar.gz 'https://example.com/download/package.tar.gz'
```

- `wget -O`：指定保存文件名，注意是大写字母 `O`。
- `curl -o`：指定保存文件名。
- `curl -L`：跟随 HTTP 重定向。
- `curl -f`：遇到 HTTP 错误状态时以失败退出，而不是把错误页当作正常下载。

后台下载与进度查看：

```bash
wget -b 'https://example.com/download/package.tar.gz'
tail -f wget-log
```

`wget` 会报告实际日志文件名；当前目录存在同名日志时，名称可能带编号。后台下载也不是托管服务，重要传输仍需确认退出状态和文件完整性。

下载软件后，可以根据发布方提供的校验值检查文件：

```bash
sha256sum package.tar.gz
```

校验值必须与可信渠道公布的值比较，单独计算一串摘要不能确认文件来源。

## 三、管理服务：systemctl 与 journalctl

下面的命令适用于由 **systemd** 管理的系统服务。容器、精简系统或其他初始化系统中，`systemctl` 可能不可用。

以已安装的 `nginx.service` 为例：

```bash
systemctl status nginx.service
sudo systemctl start nginx.service
sudo systemctl stop nginx.service
sudo systemctl restart nginx.service
```

### 区分“现在运行”和“开机启动”

| 命令 | 作用 |
| --- | --- |
| `start` | 现在启动 |
| `stop` | 现在停止 |
| `restart` | 停止后重新启动 |
| `reload` | 请求服务重载配置，需要服务支持 |
| `enable` | 按单元安装配置设置自动启动关系 |
| `disable` | 移除相应自动启动关系 |
| `enable --now` | 设置自动启动并立即启动 |
| `is-active` | 检查当前是否处于活动状态 |
| `is-enabled` | 检查启用状态 |

`enable` 通常不立即启动服务；`disable` 通常不立即停止服务，且不能阻止其他单元按依赖关系启动它。

```bash
sudo systemctl enable --now nginx.service
systemctl is-active nginx.service
systemctl is-enabled nginx.service
```

服务名因软件包和发行版而异。例如 SSH 服务可能叫 `ssh.service` 或 `sshd.service`，应先确认实际名称。

### 查看服务日志

```bash
sudo journalctl -u nginx.service -n 100 --no-pager
sudo journalctl -u nginx.service -f
sudo journalctl -u nginx.service --since '30 minutes ago'
```

日志能否查看取决于当前用户权限；`-f` 持续跟踪，按 `Ctrl+C` 退出。服务启动失败时，先读状态与日志，再决定是否重启。

修改应用配置后，通常需要应用自己的配置检查与重载；修改 systemd 单元文件后，则需要：

```bash
sudo systemctl daemon-reload
```

`daemon-reload` 让 systemd 重新读取单元定义，并不等于重启应用或让应用重读配置。

## 四、软链接：为文件提供另一个访问路径

软链接保存的是指向目标的路径，可以把它理解为一个路径引用：

```text
ln -s 目标路径 链接路径
```

例如，在家目录中为项目日志建立入口：

```bash
ln -s "$HOME/projects/demo/logs" "$HOME/demo-logs"
ls -l "$HOME/demo-logs"
```

输出中的 `->` 会显示链接保存的目标路径。

| 情况 | 结果 |
| --- | --- |
| 目标移动或删除 | 链接可能失效，成为悬空链接 |
| 目标原本不存在 | 链接仍然可以创建，但暂时无法访问目标 |
| 链接中保存相对路径 | 从链接所在目录开始解析，而非访问者当前目录 |
| `rm 链接名`，不带末尾 `/` | 删除链接本身，目标仍保留 |

如果只是为了方便执行自己的脚本，通常先考虑把脚本目录加入 `PATH`，不必向系统命令目录写入链接。

## 五、日期、时区与时间同步

查看时间与格式化输出：

```bash
date
date '+%Y-%m-%d %H:%M:%S %Z'
date +%s
```

| 格式 | 含义 |
| --- | --- |
| `%Y`、`%y` | 四位、两位年份 |
| `%m`、`%d` | 月、日 |
| `%H`、`%M`、`%S` | 时、分、秒 |
| `%Z`、`%z` | 时区名称、时区偏移 |
| `%s` | Unix 时间戳，以秒为单位 |

在支持 `timedatectl` 的系统上：

```bash
timedatectl status
timedatectl list-timezones
sudo timedatectl set-timezone Asia/Shanghai
```

时区决定时间的显示方式；时间同步负责校准系统时钟。两者是不同设置。

系统可能使用 chrony、systemd-timesyncd 或其他 NTP 客户端。先确认已有同步服务，再配置对应工具。如果已经使用 chrony，可以查看：

```bash
chronyc tracking
chronyc sources -v
```

支持相应集成的系统还可以使用 `sudo timedatectl set-ntp true` 启用可用的时间同步服务；这不负责安装缺失的软件包。

旧教程中的 `ntpd`、`ntpdate` 只适用于相应环境，不应与已有同步服务不加区分地同时启用。

## 六、环境变量与 PATH

### Shell 变量与环境变量

```bash
APP_HOME=/opt/app
export APP_HOME
printf '%s\n' "$APP_HOME"
```

第一行设置当前 Shell 变量，`export` 使之后启动的子进程继承它。也可以合写：

```bash
export APP_HOME=/opt/app
```

查看环境变量：

```bash
printenv APP_HOME
env
```

当前终端中的设置不会自动修改其他已运行的终端或服务，也不会反向修改父进程。

### PATH：命令从哪里找

`PATH` 是由冒号分隔的目录列表。Shell 查找外部命令时，会按顺序搜索这些目录。

```bash
printf '%s\n' "$PATH"
command -v bash
mkdir -p "$HOME/.local/bin"
export PATH="$PATH:$HOME/.local/bin"
```

上例把个人命令目录追加到末尾，现有目录中的同名命令优先。放在开头则会提高该目录的优先级。不要无意间覆盖整个 `PATH`，也不建议把当前目录 `.` 放进去。

### 持久配置要匹配 Shell 启动方式

| Bash 配置位置 | 常见读取场景 |
| --- | --- |
| `~/.bashrc` | 交互式、非登录 Bash |
| `~/.bash_profile`、`~/.bash_login`、`~/.profile` | 登录 Bash 按顺序读取首个存在且可读的文件 |
| `/etc/profile` | 登录 Bash 的系统级配置 |

一些发行版会在配置文件之间主动调用，具体行为应查看已有文件。其他 Shell 有自己的规则，例如 zsh 的交互配置通常在 `~/.zshrc`。

修改配置后，在确认内容正确的前提下，可以用 `source ~/.bashrc` 让当前 Bash 读取它；它不会更新其他进程。systemd 服务的环境应通过单元中的 `Environment=`、`EnvironmentFile=` 等机制配置，不能假设它会读取个人 Shell 配置。

## 七、归档与压缩：tar、zip、unzip

归档把多个文件组织成一个文件；压缩减少数据体积。`tar` 负责归档，配合 gzip 等工具可以生成压缩归档。

### tar.gz：打包、查看与解压

```bash
tar -czf project.tar.gz project/
tar -tzf project.tar.gz
mkdir -p restore
tar -xzf project.tar.gz -C restore/
```

| 选项 | 用途 |
| --- | --- |
| `-c` | 创建归档 |
| `-t` | 列出归档内容 |
| `-x` | 解包 |
| `-z` | 使用 gzip |
| `-f` | 指定归档文件，后面紧跟文件名 |
| `-v` | 显示处理的文件名 |
| `-C` | 切换到指定目录后处理后续路径 |

`-c`、`-t`、`-x` 是不同操作，一次选择一种。目标目录需要先存在；想显示处理过程，可以加入 `-v`。

解压前先查看归档内容，确认文件会放到哪里。对不熟悉的归档，优先解压到新建的空目录，避免覆盖已有项目或配置。

### ZIP：跨平台常见格式

```bash
zip -r project.zip project/
unzip -l project.zip
unzip project.zip -d restore-zip/
```

`zip -r` 递归压缩目录；`unzip -l` 查看条目；`-d` 指定解压位置。软件未安装时，先通过当前系统的软件包管理器安装 `zip` 和 `unzip`。

## 八、命令速查

| 命令 | 用途 |
| --- | --- |
| `cat /etc/os-release` | 确认发行版 |
| `sudo apt update` | 更新 APT 软件索引 |
| `sudo apt install 软件` | 安装 Debian/Ubuntu 软件 |
| `sudo dnf install 软件` | 通过 DNF 安装软件 |
| `rpm -qf 文件路径` | 查询文件所属 RPM 包 |
| `wget -O 文件 URL` | 下载并指定文件名 |
| `systemctl status 服务` | 查看服务状态 |
| `sudo journalctl -u 服务 -n 100` | 查看最近的服务日志 |
| `ln -s 目标 链接` | 创建软链接 |
| `timedatectl status` | 查看时间与同步状态 |
| `command -v 命令` | 查看当前 Shell 如何定位命令 |
| `tar -czf 归档.tar.gz 目录/` | 创建 gzip 压缩归档 |
| `tar -xzf 归档.tar.gz -C 目录/` | 解压到已有目录 |
| `unzip -l 归档.zip` | 查看 ZIP 内容 |
