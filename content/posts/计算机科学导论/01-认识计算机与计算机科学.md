计算机可以理解为一台**按照程序处理数据的通用机器**。硬件提供执行能力，数据是处理对象，软件规定处理过程。理解这三者如何配合，就能把计算机的基本概念串联起来。

## 一、计算机为什么能完成不同的任务

### 从数据处理到程序控制

如果只观察输入和输出，计算机的工作过程很简单：

```text
输入数据 → 处理 → 输出结果
```

但这种描述无法解释一个关键问题：为什么同一台机器既能计算总价，也能编辑文字、播放声音？

答案是**程序**。程序由指令组成，规定机器对数据执行哪些操作，以及按什么次序执行。改变程序，就能让同一台机器完成不同的任务。

```text
                    程序：规定处理规则
                           ↓
输入数据 ─────────→ 计算机 ─────────→ 输出结果
```

例如，对同一组数据 `3, 12, 8, 22`，采用不同程序可以得到不同结果：

| 程序 | 处理结果 |
| --- | --- |
| 从小到大排序 | `3, 8, 12, 22` |
| 求和 | `45` |
| 寻找最小值 | `3` |

可以把这种关系写成：

```text
输出结果 = 程序对输入数据进行处理的结果
```

因此，理解一次计算时，要同时看“输入了什么”和“采用什么处理规则”。程序不变而输入改变，结果可能变化；输入不变而程序改变，结果也可能变化。在确定性的计算模型中，相同程序处理相同输入会得到相同输出。

注意，“可能变化”不等于“必然变化”：两组不同的数据可能具有相同的最小值。

### 专用机器、可编程机器与通用计算

| 概念 | 关键特征 | 理解重点 |
| --- | --- | --- |
| 专用机器 | 面向特定任务设计 | 能处理数据，但任务范围受限 |
| 可编程机器 | 可以通过程序改变操作过程 | 机器行为不完全由固定结构决定 |
| 通用计算机 | 可以通过合适的程序完成不同的可计算任务 | 同一套基本执行能力可以服务于大量任务 |

会执行几种算术运算，并不直接说明机器具有通用计算能力。判断通用性，要关注它能否通过程序表达和执行足够广泛的计算过程。

### 图灵模型：把计算过程抽象出来

阿兰·图灵在 1936 年提出了通用计算设备的设想，用数学方式研究计算过程。图灵模型帮助我们从机器的具体材料、体积和结构中抽离出来，关注程序如何规定计算。

**通用图灵机的核心思想是：提供合适的程序和数据，同一台抽象机器可以执行任何可计算的运算。**

这里有两个需要分开的层面：

- **可计算性**：一个问题是否存在有效的计算方法。
- **计算效率**：采用某种方法，需要多少时间和其他资源。

两台机器能够计算同一类问题，并不表示它们处理问题的速度和规模相同。通用性也不意味着任何问题都能交给计算机解决。

## 二、一次计算中，数据、算法和程序各做什么

### 数据：被处理的对象

数字、文字、图像、声音和视频都可以成为计算机处理的数据。它们的外在形式不同，但在通常的二进制计算机内部，都需要转换成由 `0` 和 `1` 组成的位模式。

```text
数字、文字、图像、声音、视频 → 编码 → 二进制位模式
```

“都用二进制表示”不意味着这些数据含义相同。理解数据还需要知道它采用什么编码，以及应如何解释。

数据有两个相关但不同的问题：

| 问题 | 关注点 | 示例 |
| --- | --- | --- |
| 数据表示 | 怎样把信息编码成可存储、可处理的形式 | 将一个数字或字符编码为位模式 |
| 数据组织 | 怎样组合数据，使其便于管理和使用 | 将多个数据项组成记录，再形成文件或数据库 |

表示解决“怎样存进去”，组织解决“怎样安排和使用”。

### 算法：解决问题的步骤

算法是按步骤解决问题的方法。在编写程序之前，需要先想清楚：应当执行哪些操作，这些操作应按什么次序进行。

例如，求两个数之和可以分为：

1. 获得第一个数。
2. 获得第二个数。
3. 将两个数相加。
4. 给出计算结果。

算法关注求解方法；程序则用计算机能够执行的指令表达这种方法。

```text
问题 → 设计算法 → 编写程序 → 处理输入 → 得到结果
```

### 程序与计算机语言：把方法表达出来

程序是有序的指令集合。每条指令完成一定的操作，后续指令可以继续使用前面产生的数据。

计算机语言提供表达程序的符号和规则。早期编程直接面向机器指令的位模式，编写和检查都很困难。使用符号以及更高层次的语言，可以减少对底层细节的直接操作。

| 概念 | 回答的问题 |
| --- | --- |
| 算法 | 用什么步骤解决问题？ |
| 程序 | 怎样把步骤组织成可执行的指令？ |
| 计算机语言 | 用什么符号和规则表达程序？ |

### 重用：用基本操作组合复杂任务

计算机不需要为每一种任务单独设计一整套硬件。程序员可以将已有的基本指令按不同方式组合，形成不同的程序。

这种组合思想也贯穿软件的发展：公共操作可以集中实现，多个程序共同使用，从而减少重复工作。

## 三、计算机怎样把程序执行起来

### 存储程序：把操作步骤也存入机器

早期机器可以通过配线和开关设置操作过程。任务改变时，可能需要重新调整机器。

存储程序思想带来了更方便的方式：**把程序和数据一起保存在存储器中，让计算机读取程序并执行。**

```text
存储器
├── 程序：接下来要执行哪些操作
└── 数据：操作所需的输入、中间结果和最终结果
```

程序与数据都可以采用位模式存储，但用途不同：程序规定操作，数据是操作对象。更换任务时，可以更换存储的程序。

这正是冯·诺依曼模型的核心思想。

### 四个子系统及其分工

冯·诺依曼模型可以用四个子系统来理解，其中输入和输出合并为一类。

| 子系统 | 主要工作 | 记忆关键词 |
| --- | --- | --- |
| 存储器（Memory） | 保存程序、数据及处理过程中产生的结果 | 存 |
| 算术逻辑单元（ALU） | 执行算术运算和逻辑运算 | 算 |
| 控制单元（Control Unit） | 协调各子系统，组织指令的执行 | 控 |
| 输入/输出子系统（I/O） | 接收外部数据和程序，向外部传送结果 | 交换 |

同一设备可以承担输入和输出两种角色。例如，从磁盘读取数据属于输入，把结果写入磁盘属于输出。

### 指令执行：取出、解释、执行

执行程序的基本过程是：

```text
取出一条指令 → 解释这条指令 → 执行相应操作 → 确定下一条指令
       ↑                                               │
       └────────────────继续执行───────────────────────┘
```

通常继续执行后续指令，也可以通过跳转改变执行位置。例如，程序可以根据条件选择另一段指令，或返回前面的步骤。

因此，逐条执行并不意味着只能沿着程序文本从上到下运行。关键在于：机器按照程序规定的控制关系推进计算。现代计算机还会采用更复杂的安排来提高执行效率。

### 用“两数相加”串起各部分

假设输入为 `7` 和 `5`，可以把整个过程理解为：

| 步骤 | 发生的事情 | 涉及的主要部分 |
| --- | --- | --- |
| 准备 | 将程序和所需数据放入存储器 | 存储器、输入/输出 |
| 接收输入 | 读入 `7` 和 `5`，保存供后续使用 | 输入/输出、存储器 |
| 组织执行 | 读取并解释加法相关指令，协调操作 | 控制单元 |
| 完成运算 | 对两个数执行加法，得到 `12` | ALU |
| 保存并输出 | 保存结果，将结果传送到外部 | 存储器、输入/输出 |

程序负责规定步骤，控制单元负责组织执行，ALU 完成运算，存储器保存内容，输入/输出负责与外部交换信息。

## 四、把几组容易混淆的概念分清

### 图灵模型与冯·诺依曼模型

两种模型可以从不同角度帮助理解计算机。

| 比较角度 | 图灵模型 | 冯·诺依曼模型 |
| --- | --- | --- |
| 主要关注 | 如何抽象计算，怎样理解通用计算 | 怎样组织计算机，使其执行存储的程序 |
| 核心概念 | 程序控制、通用性、可计算性 | 存储程序、四个子系统、指令执行 |
| 学习时要抓住的问题 | 同一台机器为什么能完成不同计算？ | 程序放在哪里，由哪些部件配合执行？ |

学习时，可以先用图灵模型理解通用计算，再用冯·诺依曼模型理解机器的基本组织。

### 三大组成部分与四个子系统

“硬件、数据、软件”和“四个子系统”是不同层次的划分。

| 划分 | 内容 | 观察角度 |
| --- | --- | --- |
| 三大组成部分 | 硬件、数据、软件 | 从整体上看，计算机系统涉及哪些要素 |
| 四个子系统 | 存储器、ALU、控制单元、输入/输出 | 从功能上看，硬件怎样分工 |

硬件是物理基础，数据是处理对象，软件规定处理过程。四个子系统则进一步解释硬件如何支持这一过程。

### 程序、操作系统与软件工程

| 概念 | 关注重点 | 与其他概念的关系 |
| --- | --- | --- |
| 程序 | 实现某种处理过程 | 由指令组成，执行算法所描述的步骤 |
| 操作系统 | 管理计算机资源，为程序提供公共服务 | 帮助用户和应用程序访问硬件，减少重复实现公共操作 |
| 软件工程 | 用系统的原理、规则和工程方法开发软件 | 指导软件的设计与编写，而非某一条具体指令的执行 |

软件的发展不仅是让计算机执行更多指令，也包括让程序更容易编写、公共能力更容易复用，以及开发过程更有组织。

## 五、计算机的发展：哪些能力逐步出现

计算机的发展可以沿着一条线索理解：**机器代替人工运算 → 用记录控制操作 → 电子化处理 → 存储程序 → 小型化与应用普及。**

### 从机械计算到程序控制的早期探索

| 人物或机器 | 主要贡献 | 带来的思想 |
| --- | --- | --- |
| 帕斯卡：Pascaline | 用机械装置完成加减运算 | 机器可以承担算术工作 |
| 莱布尼茨：莱布尼茨之轮 | 将机械运算扩展到乘除 | 一台机器可以支持更多运算 |
| 雅卡尔：提花织机 | 用穿孔卡控制织布过程 | 可以将操作要求记录下来，由机器依次执行 |
| 巴比奇：差分引擎与分析引擎 | 探索更复杂的自动计算；分析引擎构想涉及运算、存储、控制和输入/输出 | 多种计算功能可以组织成一个系统 |
| 何勒里斯：穿孔卡数据处理机器 | 自动读取、计数和排列穿孔卡数据 | 机器可以用于大规模数据处理 |

这些机器的重要性，在于它们分别推进了自动运算、操作控制、存储和数据处理等思想。

### 早期电子计算机与存储程序

1930–1950 年是电子计算机诞生的重要阶段。代表机器包括面向方程组求解的 ABC、朱斯的 Z1、兼有电子和机械部件的 Mark I、用于密码分析的 Colossus，以及采用大量真空管的 ENIAC。

随后，EDVAC、EDSAC 等机器体现了存储程序思想。理解这一变化，比单独记住机器名称更重要：

```text
通过外部设置规定操作 → 将程序存入存储器，由机器读取执行
```

电子化推进了计算机器的发展；存储程序则改变了组织和更换计算任务的方式。

### 五代计算机：技术与应用的变化

以下采用这套教材的教学分期，时间为大致范围。

| 代际 | 大致时间 | 主要技术或形态变化 | 软件与使用方式的变化 |
| --- | --- | --- | --- |
| 第一代 | 1950–1959 年 | 真空管，体积庞大、成本高 | 商用计算机出现，主要面向大型机构和专业人员 |
| 第二代 | 1959–1965 年 | 晶体管替代真空管 | 成本和体积下降；FORTRAN、COBOL 等高级语言方便编程 |
| 第三代 | 1965–1975 年 | 集成电路、小型计算机 | 软件包进入市场，软件行业发展 |
| 第四代 | 1975–1985 年 | 微型计算机发展，代表机器有 Altair 8800 | 使用范围扩大，计算机网络发展 |
| 第五代 | 1985 年起的后续阶段 | 掌上与台式计算机、存储媒体继续发展 | 多媒体、CD-ROM、DVD、虚拟现实等应用发展 |

记忆时应抓住两条变化线索：

- **硬件方面**：器件集成程度提高，机器更小、更快，成本降低。
- **软件与应用方面**：编程更方便，软件可以作为产品提供，计算机逐步进入更多场景。

代际变化主要体现在技术和应用上，基本的存储程序思想具有持续影响。

## 六、计算机科学研究哪些问题

计算机科学涉及计算方法、机器系统、数据组织以及应用等多个方面。可以先从系统与应用两个角度建立整体认识。

| 角度 | 关注的问题 | 相关领域 |
| --- | --- | --- |
| 系统 | 计算机怎样构造、运行和协作 | 体系结构、网络、操作系统、算法、程序设计语言、软件工程、安全 |
| 应用 | 怎样使用计算机组织信息和解决问题 | 数据库、人工智能等 |

这些领域相互联系。例如，数据库既服务于信息管理，也依赖数据结构、存储和操作系统等基础能力。

### 一条连贯的学习路线

| 阶段 | 学习内容 | 建立的认识 |
| --- | --- | --- |
| 数据表示与运算 | 数字系统、数据编码与存储、基本运算 | 信息怎样进入计算机并参与计算 |
| 硬件与网络 | 计算机组成、计算机网络与互联网 | 单台机器怎样工作，多台机器怎样连接 |
| 软件与程序开发 | 操作系统、算法、程序设计语言、软件工程 | 怎样组织资源、表达方法并开发程序 |
| 数据组织与抽象 | 数据结构、抽象数据类型、文件、数据库 | 怎样管理更复杂的数据 |
| 进一步的计算问题 | 压缩、安全、计算理论、人工智能 | 怎样提高信息处理能力，理解计算边界 |
| 技术与社会 | 社交媒体和社会话题 | 计算机技术怎样影响人的生活与社会 |

这条路线把“数据如何表示”“机器如何执行”“软件如何组织”和“技术如何应用”连接起来。入门阶段先建立全貌，再深入具体领域，会更容易理解知识之间的关系。

## 七、核心概念速查

| 控制单元 | Control Unit | 组织和协调各子系统工作 |
| 输入/输出 | Input/Output，I/O | 计算机与外部交换数据和程序 |
| 操作系统 | Operating System | 管理资源并提供公共服务的软件 |
| 软件工程 | Software Engineering | 用工程方法组织软件开发 |

| 冯·诺依曼模型 | Von Neumann Model | 以存储程序及各子系统协作为核心的计算机模型 |

## 八、读完后，试着回答这三个问题

1. 对相同的输入数据，为什么换一个程序可能得到不同结果？
2. 算法、程序、计算机语言分别回答什么问题？
3. 存储程序思想中，存储器、控制单元和 ALU 各自负责什么？
