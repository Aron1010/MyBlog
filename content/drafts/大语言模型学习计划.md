# 从零开始学大语言模型：从基本概念到应用开发

这套博客面向第一次系统接触大语言模型、希望逐步做出一个可用应用的读者。先学会使用，再通过小项目接触代码；需要解释现象时，再进入计算原理。全系列以“个人学习笔记助手”为贯穿项目，每一章通过一个完整案例，说明新增能力怎样形成。

本文件是写作计划，正文位于 `../posts/大语言模型/`。文中的文章标题是选题池，可以在实际写作时合并，篇数不作为学习进度的指标。

## 一、系列的内容范围

读者应能够根据任务组织输入，用 Python 调用模型，接入自己的笔记和受控工具，并理解正确性、速度与成本的工程取舍。最后知道预训练、微调和对齐分别在做什么，以及什么时候值得采用这些方法。

前三章不要求读者先学完高等数学、机器学习或 Python。需要用到的 Python、JSON、HTTP 与环境配置，随具体任务讲解。第四章提供原理补充，第八章可以在完成应用主线后选读。

## 三、各章选题与边界

### 第 1 章：认识大语言模型

1. AI、机器学习、大语言模型是什么关系？
2. 大语言模型是什么：先分清 Token、参数和上下文。
3. 模型和聊天软件有什么区别？
4. 大语言模型可以帮你做哪些文字任务？
5. 为什么回答很流畅，也可能没有依据？
6. 一份学习笔记的整理过程：从原文到要点与安排。

这一章只建立必要直觉。保留“7B 约为 70 亿参数”等读者会遇到的说明；梯度、神经元计算、MoE、显存估算和训练数据划分放到后续章节。读者不需要先背术语才能开始使用。

### 第 2 章：把需求说清楚

1. 把“帮我整理一下”写成可以检查的任务。
2. 给一个例子有什么用，什么时候会误导？
3. 材料太长时，怎样组织上下文？
4. 表格与 JSON：格式正确和内容正确怎样分开检查？
5. 修改一次任务说明：保留问题与结果，做一次前后比较。

第二章通过完整示例说明材料、约束和输出的关系。后续章节继续使用同类笔记，讲清输入变化对结果的影响。

### 第 3 章：第一次用代码调用模型

1. 先运行起来：Python、终端、文件与环境变量。
2. API、HTTP 和 JSON：一条请求怎样来回。
3. 配置调用信息，发出第一次模型请求。
4. 从返回结果中读取文字、用量和错误信息。
5. 把一份本地笔记交给模型，保存结构化结果。
6. 处理超时、限流和流式输出，让命令行助手可以重复使用。

这里使用具体服务的文档编写可运行代码，标明版本和验证条件；不在计划阶段承诺所有服务都采用相同接口。先实现一条清楚的调用路径，再引入框架。

### 第 4 章：看懂模型的计算过程

1. 从数值到神经网络：一层计算里有什么？
2. 分词与逐步生成：一段回复怎样形成？
3. 参数、上下文与运行内存：模型规模怎样读？
4. Embedding：为什么要把文字变成向量？
5. 注意力：不同位置的信息怎样建立联系？
6. 把流程连起来：Transformer 在做什么？

这一章解释计算机制。Embedding 在这里建立表示与相似性的直觉，第五章再讲如何用它检索。自监督训练与梯度更新只作必要衔接，完整训练流程放在第八章。

### 第 5 章：让回答依据你的笔记

1. 为什么把笔记交给模型，不等于训练了模型？
2. 从文件到可用材料：读取、清理、切块与元数据。
3. 从问题到资料片段：关键词检索、向量检索与混合检索。
4. 检索后怎样回答：引用、缺失信息与冲突材料。
5. 做一个笔记问答原型，分别检查检索和回答。

用笔记中的标题、原句、更新日期和来源位置保存证据。先做一个可以回到原文核对的小系统，再讨论更复杂的检索优化。

### 第 6 章：让模型使用工具

1. 工具调用的完整过程：请求、校验、执行、返回。
2. 接入计算器：把语言判断与数值计算分开。
3. 接入只读笔记检索：参数与返回结果怎样设计？
4. 固定工作流与 Agent：什么时候需要动态决定下一步？
5. 处理失败、循环与停止条件，完成一次可追踪的工具任务。

先把一个工具调用做正确，再扩展到多步流程。模型给出操作参数，外部程序负责实际执行；完成状态必须依据工具返回结果检查。

### 第 7 章：把应用做得可靠、可维护

1. 应用质量评估：数据、标注与指标的基本组成。
2. 怎样区分回答错误、检索错误、格式错误和工具失败？
3. 记录成本与延迟：哪些步骤值得优化？
4. 缓存、并发、重试与日志：让问题可以复现。
5. 模型选择与量化：质量、内存和运行条件怎样一起比较？
6. 从本机运行到部署：配置、监测与回归检查。

这一章系统化前面已经做过的检查，不等到应用写完才第一次评估。量化和其他优化都使用实际任务复测，不把某一个资源数字直接当作效果结论。

### 第 8 章：理解训练、微调与对齐

1. 训练与推理：参数什么时候会变化？
2. 预训练与自监督学习：目标怎样从数据中形成？
3. 微调改变什么：数据、任务与参数适配。
4. 指令与偏好：怎样训练出更符合要求的行为？
5. 面对一个问题，应该改提示词、接 RAG，还是微调？

先用概念和小型示例讲清流程。具体训练另行说明数据、基线、验证方案与资源预算，使概念解释与工程实现各自有清楚的范围。

## 四、贯穿项目：个人学习笔记助手

第一章只围绕聊天界面和一份短笔记，之后才引入文件、代码与检索。项目始终围绕同一类需求：整理学习要点、查找依据、发现笔记没有提供的信息。

第一份材料使用虚构的“技术文章阅读笔记”。其中保留一条读书会安排，让读者能检查时间、负责人、待定事项和缺失渠道。案例同时展示原始材料、整理结果与依据，后续扩展时保持内容衔接。

每个阶段用输入材料、处理说明、整理结果与依据解释完整流程。正文中的人工示例与实际模型运行记录明确区分；没有运行的结果不写成测试结论。

## 五、每篇文章的写法

从一个问题或具体场景开始，解释完成本篇任务需要的概念，随后给出一个能跟着走的例子。遇到容易误读的地方，明确类比与简化的范围。文章结尾说明读者现在能做什么，以及接下来还缺哪一步。

文章采用概念讲解、完整案例和过程说明，不设置习题、自测问答、参考答案或要求读者完成的作业。对比关系用表格，过程用简短流程图，代码只在需要执行时出现。公式和术语应帮助解释问题，而不是增加学习门槛。
